# Wave 1 · J — Web demo + landing page (v1 design)

Owner of `web/` only. No build step, no JS CDN. Only Google Fonts (Geist, Geist Mono), with system fallbacks. `.nojekyll` kept.

| `web/demo/orbs.js` | **New** WebGL2 header orbs (DESIGN_SPEC §3 / research/04 Gradient spec): peach, iris and ember plus a small status orb. Each has a solid 70 % core and a smoothstep 70→100 % edge, composited in OKLab. The **halftone fringe** turns the 0.12–0.40 coverage band into a 3 css-px dot screen at 15°, with dot area equal to coverage so the tone doesn't jump; dots have a 1-device-px AA edge. There is **static** per-device-pixel grain (±4 % L scaled by coverage, ±1 % on bare paper, reseeded daily) and a triangular dither of ±1 LSB after sRGB encoding. Orbs drift on a Lissajous path (41/53/67 s, 0.05 w). `pulse()` grows ember +3 % and decays over 500 ms. Evening mode uses an ink base, orbs at 0.55 and iris at 0.6. The backing store is sized in exact device pixels (`device-pixel-content-box`, else round(css×dpr)), and rendering is capped at 30 fps. It pauses when off-screen or when the tab is hidden, and Reduce Motion freezes it. Context loss triggers a rebuild on restore, falling back to CSS after 3 s or if WebGL2 is missing. State changes morph in OKLab over 1.2 s. A `unit` option keeps phone proportions on wide pages. |

## Verification
- `node --check` passes on all 4 JS files. The page was served with `python3 -I -m http.server 8766` and captured with headless **Microsoft Edge** (Chrome isn't installed), using swiftshader WebGL inside an iframe harness at exactly 390×844, 375×812 and 1280×940. Headless Chromium can't make a window narrower than 500 px, so the harness was needed; it was deleted afterwards.
- Checked visually: crisp orbs with visible halftone fringe and grain, 1-device-px grid, tick rings, strip dots, capsule grain, sheets, dark mode, 375 px with no horizontal scroll, the desktop frame, and the landing page at desktop and 375.
- Fixes made while iterating: the status orb was muddy (green mixes to grey over peach in OKLab), so it now uses the light status tints at 0.85; the Live stream had a period-2 zigzag from a bad hash, replaced with a smooth deterministic one; only one gridline showed, so the tick rule was fixed; rate trends drawn as bars from 0 looked flat and are now lines; the first dot was clipped; minus signs were wrong. After coordinator review: (a) the orb canvas extends 28 px below the header and was painting over the top of the first card, cutting its 28 px corners on Live and Today. Cards are now `position: relative; z-index: 1`, so the gradient fades behind them and never clips. (b) Live samples were integers, so the monotone curve made a staircase. `liveSample(i)` now returns one decimal, and the displayed numbers stay rounded. live.png and today.png were re-captured and checked.

## Deviations (deliberate)
- **Status orb opacity 0.85**, not 0.5, and it uses the light tints (#9AD3B2 / #F2D46A / #E77A86) rather than the chip fills. At 0.5 over peach it read as olive mud.
- **HR line is ink with an ember-tinted grained fill.** research/04 says to use the series colour for the fill; ink fill looks grey on paper. This matches design/v1-direction r-screens.
- **Body rows**: vitals (resting HR, HR asleep, breathing, SpO2) show the dot-matrix strip in the row, and the other metrics show the baseline ribbon. Both appear in the MetricSheet.
- The Live ticker says "N s ago" because the demo appends every 3 s; iOS says "N min ago".
- Range strip: the "your usual" dots are always green (good) and the result's flag is carried by the chip and the pill label. Tinting the band red when out of range read as "your usual is bad".
- Rounded numerals use `ui-rounded` (SF Rounded on Apple devices), falling back to Geist elsewhere.
